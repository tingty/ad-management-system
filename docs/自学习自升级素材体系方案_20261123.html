广告素材体系：自学习 · 自探索 · 自升级

基于现有《广告管理系统》的最小改动演进方案 —— 解决风格趋同、冷启动无数据、趋势捕捉与人工缺口

一、先自查：你的困惑是否真实存在？

我按当前代码逐项核对，四个困惑都真实存在，且能定位到具体机制；同时发现系统已具备约六成的基础能力，不需要重做。

困惑核实代码层面的真实原因
① 输出风格统一、不理想真实 CONCEPT_AXES 固定三轴、SCENE_TEXT 按行业写死、concept_count 默认 1；按模板创作一次只注入 routes:[1条]；提示词库 BEST_PRACTICES（AIDA/PAS…）是静态人工预设。输入固定 → 输出必然趋同。
② 无数据佐证真实 数据模型中没有任何效果或评分表；但 CreationHistory 已存 prompt_hash / config_snapshot，具备做版本化追溯的基础。
③ 无专业研究员跟进真实 解构与归并目前依赖逐条人工确认，没有批量趋势判断与优先级排序。
④ 捕捉不到设计动向真实 fetchers 只抓落地页做事实取证，web_screenshot 只做网页截图；没有定期外部素材采集，也没有跨批次差异分析。
已经具备、可直接复用的基础：素材三表（原件 / 解构 / 模板）、12 类主分类 + 目的/钩子/信息结构相似度、golden 完整度择优、真实视觉模型与 unavailable 降级、D0 证据门、品牌文字三道防线、现成的定时调度模式（model_health 日调度 / creative_tasks worker）。

二、对你方案的综合判断：方向对，但要做三处关键升级

你提出的「采集 → 解构归档 → 模板库 → 创作 →（未来）反馈」三段式划分是正确的，也符合现有系统结构。但按原样实施会卡在三个地方：

升级 1 · 采集不是一次性建库

素材设计会随时间变化。必须给每批采集打时间标签，做跨批次差异对比，否则模板库会固化在某一时段的风格上。

升级 2 · 不等投放数据才开始学习

冷启动期用「结构完整度 / 多样性 / 合规 / 一键采用」等弱信号先跑起来，把学习定义为知识资产的积累，而不是等数据回流。

升级 3 · 创作端要从「套模板」改成「选范式」

当前一条模板 = 一种风格。改成按场景检索多条候选范式、每条路线绑定不同骨架，才能从根上打破趋同。

重新定义「自学习」：不是模型自己改代码，而是三件事形成闭环 —— ① 外部优秀素材被解构成可检索的结构化范式；② 每次创作沉淀可度量的弱信号；③ 弱信号调整范式的检索权重。每一次调整都有版本号、可回滚、可追溯。

三、整体使用流程与设计目的

四、四个困惑的逐项解法

困惑解法依赖
① 风格趋同、输出不理想 三处改动：(a) 概念轴从模板库钩子类目动态选取，替代固定 CONCEPT_AXES；(b) creative_plan.routes 由 1 条改为按场景检索的 N 条，每条绑定不同范式骨架；(c) 把高频但不适配本次目标的范式作为反例提示。外部素材只借表达结构，产品事实仍走证据门。 P0 新增
② 无数据佐证 建立代理指标：结构完整度（复用 completeness）、表达多样性（复用 information_similarity 距离）、合规一致性（复用品牌词典 / 视觉审核）、创作者一键采用/弃用。加权成「范式成功率」，作为检索排序依据。真实投放数据到来后，只需替换权重来源，不改结构。 P2 新增
③ 无研究员实时跟进 把研究员工作拆成机器可做与人工少量确认：机器批量解构、归类、算频率变化并生成「趋势简报」；人只做两件事 —— 确认归并建议、对产出一键采纳/弃用。不做复杂评审界面。 P1+P2
④ 捕捉不到设计动向 复用现有 scheduler 做定期采集，每批打时间标签；对最近 N 批与前 N 批做特征频率 diff，输出上升/下降的钩子、构图、配色、信息结构，形成趋势简报并写入模板的时效权重。 P1 新增

六、落地边界：严格遵守你的设计要求

  • 不改菜单配置：不新增一级菜单，不改名、不重定向旧 hash。采集任务与趋势简报作为现有「素材创意模板库」页面内的卡片/分区呈现；多范式选择嵌在现有「按模板创作」内。
  • 不改界面风格：复用现有 CSS 变量与卡片样式，新增元素沿用同一视觉语言。
  • 不改现有功能：默认创作链路、解构/归并结果、模板编辑、下载导出全部保持原行为；新能力以增量方式接入，可单独关闭。
  • 数据模型最小增量：只增加三张轻量表 —— 采集批次、范式统计、轻评分；现有三表只加字段不重建。旧库可平滑迁移。
  • 诚实原则不变：视觉模型不可用时标 unavailable，不静默 Mock；外部素材不自动采信为事实；所有输出保留可追溯链路。

七、建议实施顺序

P0 · 先解决最痛的趋同问题
多范式检索 + 动态概念轴 + 反例约束。只用库内已有素材，不依赖外部采集与数据，投入最小、见效最快。
P1 · 让外部优秀素材持续进来
定期采集调度 + 批次标签 + 趋势 diff + 趋势简报，接入现有模板库。
P2 · 让「自学习」真正闭环
轻评分 + 代理指标 + 范式成功率排序 + 版本回滚。
P3 · 预留，不开发
投放数据关联键与字段占位，等传输机制建立后再接。
每一阶段独立成版（V4.124 起）、独立测试、独立发版，沿用现有 CHANGELOG / 发布数据 / 提交推送流程。任何阶段可单独暂停，不影响已上线功能。

八、需要你确认的决策点

Q1 · 采集源优先级
先做哪类来源？（A）媒体广告库公开素材 （B）第三方素材分析平台 （C）竞品落地页自动截图 （D）仅人工上传。建议先做 D+C，合规风险最低、实现最快。
Q2 · 采集频率与规模
每周一次 / 每日一次？每批上限多少条？建议每周一次、每批 50 条，先观察质量再调。
Q3 · 外部素材的合规边界
原图是否长期归档？建议沿用现有策略：原图长期归档、只学表达结构、不继承品牌与事实；如你要求不落原图，可改为只存解构结果。
Q4 · 新增入口形式
「采集任务 / 趋势简报」放在模板库页面内独立分区，还是嵌进现有 Tab？建议独立分区，不动现有 Tab 结构。
Q5 · 轻评分是否接受
创作者对产出做「采用 / 弃用」一键点选，作为冷启动学习信号。若不接受，则 P2 只能等投放数据，自学习闭环会延后。
Q6 · 是否按 P0 → P1 → P2 顺序开发
还是希望先做采集（P1）？建议 P0 优先，因为它不依赖任何外部条件且直接针对「输出不理想」。
