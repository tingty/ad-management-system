四、解构分析框架

4.1 固定六步流程

  1. 导入登记：本地上传 / 图片 URL / 网页截图 / 视频上传；写来源、平台、版权标注。
  2. 规范化：读宽高格式；视频抽首/中/尾帧 + 记时长（一期只归档 + 封面帧，解构放 V4.121）。
  3. 视觉解构：逐项分析构图 / 动线 / 色彩 / 主体（视觉模型不可用标 unavailable，不臆测）。
  4. 结构与文案解构：信息层级、标题角色、卖点、CTA、字画分工。
  5. 效果推断：Q3 已定：仅创意 / 传达层，标注"非投放数据"。
  6. 分类 + 模板归属：按第五节打分类标签，给归属建议 + 差异 + 置信度。

4.2 维度字典

图片

视频专属（V4.121）
前 3 秒钩子、时长分镜、镜头语言、字幕/VO 分工、音乐情绪、信息递进与收口 CTA

4.4 网页链接自动截图（Q2 新增能力 · 技术依赖）

结论：可做，但它是本方案唯一新增的部署依赖，需在 V4.118 开工前确认真实环境能装浏览器。
  • 新增接口：POST /api/assets/screenshot，入参 {url, mode: viewport|fullpage}；headless chromium 打开 → 截图 → 写入 uploads/ → 复用 fetch-url 的入库与标注逻辑。
  • 部署前置：docker 镜像预装 playwright + chromium（约 150MB）；或用已有截图服务。本机已有 chromium 可用于开发验证，但真实环境需单独确认。
  • 安全（必须）：SSRF 防护 —— 只允许 http(s)、禁止内网/回环/私有 IP、DNS 解析后复检、屏蔽重定向到内网；超时 20s、限制最大页面高度与图片大小。
  • 诚实标注：登录墙 / 验证码 / 纯动态渲染页可能截不到完整内容，结果一律标"网页截图 · 内容完整性未保证"，不冒充有效素材。

五、分类体系详设（Q4 商议重点）

分类要同时服务三件事：检索（找得到）、归并（判得准"大同小异"）、模板归属（这条属于哪种模板）。单一树形分类会失真，因此采用「一层主分类轴（必填，单一）+ 多维辅助标签（多选）」的混合体系。

5.1 体系总览

主分类轴（必填 / 单一）＝ 创意套路 12 类 → 决定"这是哪类模板"
＋ 辅助标签（多选 / 可空）＝ 目的 · 行业 · 平台 · 形态 · 风格 · 情绪 · 钩子 · 证据 · 合规
＝ 归并键（主分类 + 目的 + 钩子 + 信息结构相似度） → 候选组 → 人工确认 → 唯一表达

5.4 归并键 + 唯一表达（框架完整度口径）请商议评分口径

归并键：主分类相同 + 推广目的相同 + 钩子类型相同 + 信息结构相似度 ≥ 阈值 → 进入同一归并候选组 → AI 建议 + 人工确认（Q5）。被归并素材软保留、标 merged_to_template_X，可取消。

唯一表达按"框架完整度"（Q6）：完整度 = 必填维度中"有值且置信度 ≥ 0.6"的比例。选完整度最高的素材作为 golden 表达。

必填维度组（图片 12 项）计分项
布局构图套路 / 视觉动线 / 主体位置
视觉配色 / 光线 / 质感
信息标题角色 / 卖点 / CTA / 证据形式

六、素材工作坊"按模板创作"模式

6.1 交互：增量开关，默认模式不动

输入卡顶部加二选一模式条：默认 · 素材创作（完全不变）/ 按模板创作（新增）。

6.2 模板模式创作链路

  1. 选择一个模板（单选；Q10：模板作为路线来源之一，模板骨架落成一条路线，不另建规划逻辑）。
  2. 仍需输入新产品信息 / 链接 —— 模板决定"怎么表达"，产品事实来自新输入。
  3. Q9：模板只影响图片 —— 把图片骨架（构图 / 信息层级 / 钩子 / CTA 形式）注入 images_request；文案链路不受模板影响，仍按原 analysis + brief 生成。
  4. 证据护栏：骨架只给结构，卖点 / 数字仍取自自家 evidence_index，不照搬参考素材事实。
  5. 结果挂 template_id；出图卡标"按模板X出图"，文案卡不标模板。
关键护栏：模板 = 表达骨架，不是"别人素材的 prompt 直接拿来用"，否则把竞品事实带进自家素材，触发编造与侵权，与 D0 证据门冲突。
