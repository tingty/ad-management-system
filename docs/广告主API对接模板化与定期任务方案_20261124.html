广告主 API 对接模板化：定期请求任务与界面设计需求方案

全新一级功能模块 · 独立界面布局 · 把 CJ 联盟佣金接口抽象为标准模板，用户只填必填信息即可创建请求任务

〇、需求定位与隔离边界

已确认的定位：这是一个全新一级功能模块——新增一级菜单入口，界面布局与结构完全按本需求独立设计；不改动任何现有功能模块的菜单、界面布局与功能实现。现有模块（素材工作坊、创意工作台、素材创意模板库、素材标准库、提示词管理、素材历史、系统设置等）保持原样，新旧之间仅共享登录态与基础组件样式变量。

设计目的：把「某个渠道的接口怎么调」沉淀成标准模板，把「本次用哪个账号调」变成实例配置。以后接入新的联盟 / 广告主 API，只需新增一份模板，不改业务代码。CJ 是第一个落地模板。

关于凭据：你提供的 API Token 未写入任何文件。正式实现中，Token 由界面密码框输入、加密存储、列表脱敏、不回显、不写日志、不下发前端。
隔离保证：新增一级路由与独立页面组件；现有页面的 Tab 枚举、菜单分组、布局与交互代码不做任何修改；新增数据表独立命名，通过 ensure_schema() 增量建表，不影响现有表结构。

二、定期请求任务规划

任务项规划
任务绑定一个任务绑定一个 API 连接实例；一个实例可建多个任务（如"日报"与"历史回填"）。
调度方式复用现有 model_health 的 startup 后台协程模式，新增佣金拉取协程；启停对称，不引入新调度框架。
触发频率默认每日一次（可配置为每 6 小时）。任务配置含：频率、回溯窗口（默认 7 天）、首次回填天数（默认 90 天）。
执行流程按模板窗口切片 → 游标翻页 → 限流等待 → 原始落库（幂等 upsert）→ 重算事实表 → 写运行记录。详见下表。
水位管理按 postingDate 重叠窗口拉取；水位与游标写入 SystemState / 运行记录，重启后可续跑。
失败处理认证失败 / count=0 / 字段异常 / 超限分别给出明确错误；指数退避重试；失败不静默，运行记录可见并可手动补拉。
数据落地原始层 cj_commission_raw（永不删）→ 事实层 cj_commission_fact（修正合并、取消单识别）→ 报表聚合。共用上一版方案的数据设计。
可观测每次运行记录：起止时间、窗口、拉取条数、游标位置、状态、错误；界面「运行记录」区可查，支持"获取难点排查"。

任务执行子步骤（模板驱动）

  1. 读取实例配置（Token / CID / Endpoint）与模板规则，校验必填项完整。
  2. 确定窗口：当日任务 = 最近 7 天；回填任务 = 从起始日按 ≤31 天分片。
  3. 用模板查询骨架发起请求，带 sincePostingDate / beforePostingDate / forPublishers。
  4. 解析响应，按模板字段映射写入原始层，commissionId 幂等去重。
  5. 若 payloadComplete=false，取 maxCommissionId 作游标继续；否则进入下一窗口。
  6. 全窗口完成后重算事实层（合并修正、标记取消单），更新水位与运行记录。

三、界面设计需求方案

菜单与路由（已定稿）：新增一级菜单项 「广告主API」，与现有分组平级；独立 hash 路由（建议 #/advertiser-api），独立页面组件。现有菜单分组与路由一项不改。权限：viewer 只读，editor 可建连接与任务，admin 可管理模板与查看全部运行记录。
布局原则：独立页面内单页分区、无多层弹窗；沿用全局 CSS 变量以保证视觉一致，但页面结构按本需求独立设计；现有各功能页的布局与交互不受影响。

3.3 交互与状态要求

  • 测试连接：用 1 天窗口发真实请求，返回"成功 / 认证失败 / CID 无效 / count=0"，测试记录进日志；不通过不允许启用任务。
  • 状态流转：连接 = 未验证 / 已验证 / 失效；任务 = 草稿 / 运行中 / 暂停 / 失败；运行 = 成功 / 部分成功 / 失败。
  • 脱敏：Token 列表仅显示尾号，编辑时不回显原值，留空表示沿用已存值。
  • 可追溯：每次拉取可回看窗口、条数、游标与错误；支持手动"立即拉取"补数。
  • 不改现有：不改动素材工作坊 / 创意工作台 / 模板库等现有页面的菜单、布局与功能。

四、数据结构（最小增量）

表 / 配置用途
api_channel_template模板定义（种子数据，预置 CJ 模板），只读；字段以 JSON 存请求骨架、分页协议、限流、映射规则。
api_connection连接实例：名称、模板 ID、Endpoint、CID、加密 Token、状态、最后验证时间。
api_fetch_task任务：实例 ID、频率、回溯窗口、回填天数、状态、下次执行时间。
api_fetch_run运行记录：窗口、游标、条数、耗时、状态、错误详情。
cj_commission_raw / cj_commission_fact原始数据与修正合并后的事实表，报表唯一数据源。
SystemState KV复用现有 KV 存水位、全局开关；Token 不进 KV 明文。
