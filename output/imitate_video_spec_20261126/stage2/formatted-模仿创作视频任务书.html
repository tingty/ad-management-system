执行摘要

本任务书将「模仿创作视频」定义为《广告管理系统》中一个独立的、一级菜单级功能模块，入口 #/imitatevideo。它以一条专业投放视频（链接或本地上传）为学习对象，系统性解构其创作方案，输出完整的分析脚本；再叠加用户创作选项，重新演绎出内容独立、符合目标媒体投放规格的创作脚本；最后复用系统现有大模型配置、租约任务 worker 与视频三道防线，逐镜生成并复核出片。

与系统现有「创意工作台」以落地页/产品事实 + 证据链为输入不同，本模块以「一条完整参考视频」为输入，产出「模仿其结构与方法论、但内容与画面全新」的再创作视频。其存在价值在于：现有视频创作链路未产生理想案例，本模块通过向好老师学习的方式加强优质视频素材的生成能力。

本任务书基于用户提供的《AI视频重制工作台 V1.0 草案》及本轮对话已确认的规划口径编制，是参数冻结后的开发与验收依据。源草案中挂靠平台、技术栈、权限模型、模型配置等假设与现有系统不符，已逐项纠偏（见第一章）。C-M1 至 C-M8 待确认事项用户已答复「没有异议」，全部按建议默认值执行（见第十章）。

（一）定位

表 2-1 模块定位

（二）核心概念：双脚本模型

本模块的核心资产是两个维度对齐、内容独立的脚本：

  • 分析脚本（交付物①）：对原视频逐层解构，产出完整、系统、具象的结构化文档，回答"这条视频为什么有效、它是怎么做出来的"。
  • 创作脚本（交付物②）：叠加用户创作选项后，基于分析脚本重新演绎，产出内容全新、可直接驱动生成的分镜指令，回答"我们要做一条怎样的新视频"。

两者的维度一一对应（内容布局/结构/细节/画面要求/运动轨迹/颜色特点/拍摄手法等），但创作脚本的内容不得逐字复制原片——这是"模仿方法论、不复制内容"的落地方式。

（三）模仿边界

  • 模仿：分镜数量与顺序、时长节奏、钩子与 CTA 位置、叙事框架、运镜与构图倾向、色彩风格、拍摄手法、画面分区布局。
  • 不复制：字幕文本、真人话术、原片品牌 Logo、承诺性数字、未经核实的宣传声明。
  • 可选保留：品牌名、文案、销售信息、促销信息——由用户逐类勾选，且必须经改写后呈现（C-M1）。

四、功能需求详述

（一）源视频获取（S1）

  • 双入口 Tab：链接输入（服务端代下载，SSRF 校验，直链优先）与本地上传（复用 /api/assets/upload-video）。
  • 字段：任务名称、输入来源、源链接或视频文件、目标语言（英文/中文/跟随原片）、目标时长（15/30/60 秒/跟随原片）、结构保持度（高/中/低）、目标投放位（平台+版位，必选）、产品卖点/品牌、AI 标识开关、权利声明勾选。
  • 校验：URL 格式校验、仅 http/https、私有网段 SSRF 拦截；时长建议 10–120 秒、体积 ≤200MB，超限明确失败原因；非视频容器拦截。nginx 上传上限由 50MB 放宽至 200MB。
  • 元数据：时长、画幅、分辨率、帧率、容器、音轨有无，由 verify_video_file() 提取。
  • 边界用例：非直链/需登录/防盗链 → 提示改贴直链或走上传；无音轨/无画面文字 → 标"无"不猜测。

（二）分析脚本生成（S2）

  • 抽帧：逐镜 3–5 帧 + 全局取色 + VLM 逐帧理解（C-M3），不引入新模型用途。
  • 底层能力：复用 extract_frames/recognize_frames/deconstruct_video，产出后由 LLM 归纳为完整分析脚本（字段见第五章）。
  • 视觉模型不可用时标 unavailable，不冒充已复核、不误伤成片。
  • 同链接按 file_hash 缓存 S2 结果；用户可查看与导出分析脚本（结构化 JSON + 可读视图）。

（三）创作脚本生成与确认闸门（S3/S4）

  • 统一文本模型把「分析脚本 + 用户创作选项」转成完整创作脚本（字段见第五章）。
  • 确认页展示：原片/新片结构对照、逐镜创作指令表、商业信息"原文→改写后"对照、预计消耗。
  • 用户可逐句改写旁白、删镜、排序、调整结构保持度；确认后才提交计费生成。
  • 模型未过 last_test_ok → 422 拦截，不产生费用。

（四）逐镜生成与复核（S5/S6）

  • 生成：复用 get_video() → ModelVideo.submit_job/poll_job 逐镜生成；首期逐镜"干净首帧 + 运动 prompt"，不依赖多帧参考。
  • 落盘：save_video_media() + verify_video_file()；规格复核 validate_video_delivery()，按目标投放位规格强校验，不跟随原片画幅。
  • 拼接与文字：按 C-M1 决策执行（见第六章）；视觉 OCR 复核沿用三道防线，标 TEXT_VISION_MISMATCH / needs_attention。
  • 幂等：拿到 provider_task_id 立即落库；重启按号续查；只有 regenerate 才产生新费用。
  • 交付：在线 video 播放器预览、成片与中间产物下载、归档 CreativeAsset；单段失败重试一次后标 needs_attention，不阻塞整体。

六、商业信息呈现与三道防线（C-M1 决策）

用户确认采用方案 A：改写后的商业信息文字烧录进成片，投放平台通用、下载带字。

  • 受控例外：在现有"画面零文字 + 播放层 DOM 叠加 + 真实视觉 OCR 复核"三道防线上开一个例外——仅本模块、仅用户勾选、仅经改写与词典校验的文字允许烧录；通用默认仍是原片零文字。
  • 实现路径：品牌字样不交给视频模型画（避免模型画字错误），由后端在复核通过后按创作脚本时间轴烧录；烧录后做真实视觉 OCR 复核，比对词典，违规标 TEXT_VISION_MISMATCH / needs_attention，原片保留核对。
  • 改写约束：字幕与真人话术不得逐字复制原片；商业信息须经 LLM 改写并从文案层进入烧录流程。
  • 能力缺口：系统当前无系统 ffmpeg/ffprobe、无 ASS/drawtext 烧录组件，烧录能力为 V4.149 必须新建项（本项目内实现，不引入独立大模型配置）。

七、页面设计与交互

页面三段式，均在 #/imitatevideo 内：

  1. 新建任务区：双 Tab（链接/上传）+ 字段表单 + 商业信息四类勾选 + 权利声明勾选。
  2. 脚本确认区：分析脚本查看/导出；原片与新片结构对照；逐镜创作指令表（可改写旁白、删镜、排序、调结构保持度）；商业信息"原文→改写后"对照；预计消耗；"确认并生成"按钮。
  3. 任务列表区：状态、当前阶段、各阶段耗时、中间产物（脚本表/分段视频/音频）、成片预览与下载；全局 Dock 角标显示进行中任务数。

进度订阅提升到 App 层常驻（useCreativeTasks 上提），切页/刷新/关浏览器后任务不中断，回来可续看进度与状态。

（一）技术红线

  • 不新建大模型配置模块；禁用 Mock/Fallback 冒充交付。
  • 任务事实只有一份，禁止进程内任务字典；kind=="video" 硬编码需在 _claim/recover/_drive 三处放开。
  • SQLite 时间统一 naive UTC；worker 每步释放 lease_until。
  • 只有 save_video_media + verify_video_file 通过才算成功。
  • 参考视频不是已核实产品事实，不能沿用落地页 [E###] 证据契约。

（二）每版验收

专项 unittest + 隔离库全量回归 + npx tsc --noEmit + npm run build + prepare_release --sync/--check + CHANGELOG 独立版本条目 + tag + push。
