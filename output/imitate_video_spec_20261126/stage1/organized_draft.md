# 模仿创作视频 需求规格与技术开发任务书

## 执行摘要

本任务书将「模仿创作视频」定义为《广告管理系统》中一个独立的、一级菜单级功能模块，入口 `#/imitatevideo`。它以一条专业投放视频（链接或本地上传）为学习对象，系统性解构其创作方案，输出完整的**分析脚本**；再叠加用户创作选项，重新演绎出内容独立、符合目标媒体投放规格的**创作脚本**；最后复用系统现有大模型配置、租约任务 worker 与视频三道防线，逐镜生成并复核出片。

与系统现有「创意工作台」以落地页/产品事实+证据链为输入不同，本模块以「一条完整参考视频」为输入，产出「模仿其结构与方法论、但内容与画面全新」的再创作视频。其存在价值在于：现有视频创作链路未产生理想案例，本模块通过"向好老师学习"的方式加强优质视频素材的生成能力。

本任务书基于用户提供的《AI视频重制工作台 V1.0 草案》及本轮对话已确认的规划口径编制，是参数冻结后的开发与验收依据。源草案中挂靠平台、技术栈、权限模型、模型配置等假设与现有系统不符，已逐项纠偏（见第一章）。C-M1~C-M8 待确认事项用户已答复「没有异议」，全部按建议默认值执行（见第十章）。

## 一、编制依据与草案纠偏

### 1.1 编制依据

- 源草案：《AI视频重制工作台 产品功能策划 V1.0》（2026-11-26），提供 F1–F6 模块、S1–S6 管线与五类模型调用的原始设想。
- 用户三条核心要求：以专业投放视频为学习对象、尽可能消化其创作方案；商业信息可作为选项保留但须优化调整；输出完整且具象的分析脚本与创作脚本；新片符合媒体投放规格；保持新片独立与创新、不直接复制。
- 现有系统架构只读调研结论（见 1.3）。

### 1.2 草案纠偏对照

源草案多处技术假设与现有《广告管理系统》真实实现不符，本任务书按下列口径纠偏：

| 编号 | 源草案假设 | 系统真实情况 | 本任务书口径 |

## 二、模块定位与边界

### 2.1 定位

| 维度 | 定义 |
|------|------|
| 名称 / 入口 | 「模仿创作视频」，独立一级菜单，单入口 `#/imitatevideo`（无需改 tabFromHash） |
| 独立性 | 与素材工作坊、创意工作台、广告主数据、系统设置并列；不改这 4 个模块的布局与功能 |
| 与创意工作台的区别 | 现有链路输入为落地页/产品事实 + 证据门；本模块输入为一条完整参考视频，产出模仿其结构的再创作视频 |
| 大模型 | 只读 `model_configs`，走 `get_llm_with_info`/`get_video`；不新建配置模块、不改 LLMSettings |
| 任务不中断 | 任务事实存 `generation_jobs`/`creative_batches`，租约 worker 驱动；进度订阅提升到 App 层常驻，全局 Dock 角标，切页/刷新/关浏览器均可回看 |

### 2.2 核心概念：双脚本模型

本模块的核心资产是两个维度对齐、内容独立的脚本：

- **分析脚本（交付物①）**：对原视频逐层解构，产出完整、系统、具象的结构化文档，回答"这条视频为什么有效、它是怎么做出来的"。
- **创作脚本（交付物②）**：叠加用户创作选项后，基于分析脚本重新演绎，产出内容全新、可直接驱动生成的分镜指令，回答"我们要做一条怎样的新视频"。

两者的维度一一对应（内容布局/结构/细节/画面要求/运动轨迹/颜色特点/拍摄手法等），但创作脚本的内容不得逐字复制原片——这是"模仿方法论、不复制内容"的落地方式。

### 2.3 模仿边界

- 模仿：分镜数量与顺序、时长节奏、钩子与 CTA 位置、叙事框架、运镜与构图倾向、色彩风格、拍摄手法、画面分区布局。
- 不复制：字幕文本、真人话术、原片品牌 Logo、承诺性数字、未经核实的宣传声明。
- 可选保留：品牌名、文案、销售信息、促销信息——由用户逐类勾选，且必须经改写后呈现（C-M1）。

## 三、端到端管线与状态机

### 3.1 管线阶段

| 阶段 | 名称 | 输入 | 输出 | 责任方 | 产生费用 |
|------|------|------|------|--------|---------|
| S1 | 源视频获取 | 链接 URL 或本地文件 | 源视频文件 + 媒体元数据 | 后端下载/上传服务 | 否 |
| S2 | 分析脚本生成 | 源视频 | 完整分析脚本（见第五章） | VLM 分析 + LLM 归纳 | 是（分析模型，缓存复用） |
| S3 | 创作选项与脚本生成 | 分析脚本 + 用户选项 | 完整创作脚本（见第五章） | LLM 文本模型 | 是（脚本模型） |
| S4 | 确认闸门 | 创作脚本 | 用户确认后的脚本 | 用户 | 否 |
| S5 | 逐镜生成 | 逐镜生成指令 | 分段视频片段 | 图生视频模型 | 是（主要成本） |
| S6 | 复核与交付 | 片段 + 脚本 | 成片 + 中间产物 + 归档 | 后端 + 前端 | 否 |

两条输入路径（链接 / 上传）在"源视频文件"处汇合，S2 之后完全一致。同链接按 file_hash 复用 S1/S2 结果，不重复计费。

### 3.2 状态机

| 层 | 取值 |
|----|------|
| 用户可见 | 已创建 → 获取源视频 → 结构分析 → 待确认 → 生成中 → 复核中 → 已完成 / 需关注 / 失败 / 已取消 |
| 后台 stage | `source_acquiring → analyzing → planning → awaiting_confirm → submitting → provider_pending → downloading → validating → completed` |
| 失败口径 | 无片 = `needs_attention`；服务端 bug = `failed`；拿到 provider_task_id 立即落库，重启按号续查**不重提** |

状态流转红线：worker 每步结束必须释放 `lease_until`；SQLite 时间统一 naive UTC；只有 `save_video_media` 落盘并通过 `verify_video_file` 才算 succeeded，分镜永远只是兜底交付物。

## 四、功能需求详述

### 4.1 源视频获取（S1）

- 双入口 Tab：链接输入（服务端代下载，SSRF 校验，直链优先）与本地上传（复用 `/api/assets/upload-video`）。
- 字段：任务名称（默认取文件名/链接末段，可改）、输入来源、源链接或视频文件、目标语言（英文/中文/跟随原片）、目标时长（15/30/60 秒/跟随原片）、结构保持度（高/中/低，定义见 C-M8）、目标投放位（平台+版位，必选，C-M6）、产品卖点/品牌（再创作依据）、AI 标识开关、权利声明勾选（C-M5）。
- 校验：URL 格式校验、仅 http/https、私有网段 SSRF 拦截；时长建议 10–120 秒、体积 ≤200MB，超限明确失败原因；非视频容器拦截。nginx 上传上限由 50MB 放宽至 200MB。
- 元数据：时长、画幅、分辨率、帧率、容器、音轨有无，由 `verify_video_file()` 提取。
- 边界用例：非直链/需登录/防盗链 → 提示改贴直链或走上传；无音轨/无画面文字 → 标"无"不猜测。

### 4.2 分析脚本生成（S2）

- 抽帧：逐镜 3–5 帧 + 全局取色 + VLM 逐帧理解（C-M3），不引入新模型用途。
- 底层能力：复用 `extract_frames`/`recognize_frames`/`deconstruct_video`，产出后由 LLM 归纳为完整分析脚本（字段见 5.1）。
- 视觉模型不可用时标 `unavailable`，不冒充已复核、不误伤成片。
- 同链接按 file_hash 缓存 S2 结果；用户可查看与导出分析脚本（结构化 JSON + 人类可读视图）。

### 4.3 创作脚本生成与确认闸门（S3/S4）

- 统一文本模型把「分析脚本 + 用户创作选项」转成完整创作脚本（字段见 5.2）。
- 确认页展示：原片/新片结构对照、逐镜创作指令表、商业信息"原文→改写后"对照、预计消耗。
- 用户可逐句改写旁白、删镜、排序、调整结构保持度；确认后才提交计费生成。
- 模型未过 `last_test_ok` → 422 拦截，不产生费用。

### 4.4 逐镜生成与复核（S5/S6）

- 生成：复用 `get_video()` → `ModelVideo.submit_job/poll_job` 逐镜生成；首期逐镜"干净首帧 + 运动 prompt"（C-M12 沿用现有能力），不依赖多帧参考。
- 落盘：`save_video_media()` + `verify_video_file()`；规格复核 `validate_video_delivery()`，按 C-M6 选中的目标投放位规格强校验，不跟随原片画幅。
- 拼接与文字：按 C-M1 决策执行（见第六章）；视觉 OCR 复核沿用三道防线，标 `TEXT_VISION_MISMATCH` / needs_attention。
- 幂等：拿到 provider_task_id 立即落库；重启按号续查；只有 regenerate 才产生新费用。
- 交付：在线 `<video>` 预览、成片与中间产物下载、归档 `CreativeAsset`；单段失败重试一次后标 needs_attention，不阻塞整体。

## 五、分析脚本与创作脚本完整规格

本章是"越详细越好、越具象越好"要求的落地定义，是开发的核心数据契约。

### 5.1 分析脚本字段规格（交付物①）

| 组 | 字段 | 说明 | 数据来源 |

| A2 叙事骨架 | 前 3 秒钩子手法、情绪曲线、卖点排布顺序、CTA 时机与形式、信息密度节奏 | VLM 逐帧 + LLM 归纳 |

| A5 运动轨迹 | 每镜主体运动方向与路径、镜头运动路径、屏内元素运动速度 | 逐帧 VLM 理解 |

| A7 商业信息 | 品牌名/文案/销售/促销原文、出现时机与位置、字幕样式、口播逐字稿与语速 | OCR + VLM |
| A8 音频 | BGM 风格与卡点、音效节点、口播停顿重音 | 音轨分析（首期仅有无+节点） |

### 5.2 创作脚本字段规格（交付物②）

| 组 | 字段 | 说明 |
|----|------|------|
| C1 目标规格 | 从 `media_spec_library` 按 C-M6 选中的目标投放位取唯一规格 | 前端零硬编码 |
| C2 结构方案 | 逐镜时长/顺序/钩子/CTA，结构保持度按 C-M8 高/中/低 | 高=逐镜时长顺序全保留；中=保留钩子与 CTA；低=仅保留叙事骨架；均可逐镜微调 |

| C4 风格方案 | 继承 A6 色系光影并按品牌色校正 | 风格保持与创新平衡 |
| C5 商业信息方案 | 品牌/文案/销售/促销四类开关 + "原文→改写后"对照 | 标注未逐字复制，C-M1 |
| C6 字幕/话术方案 | 新文案、样式、停留时长、口播改写稿 | 口播仅交付文案、人工配音，C-M2 |

## 六、商业信息呈现与三道防线（C-M1 决策）

用户确认采用方案 A：改写后的商业信息文字**烧录进成片**，投放平台通用、下载带字。

- 受控例外：在现有"画面零文字 + 播放层 DOM 叠加 + 真实视觉 OCR 复核"三道防线上开一个例外——仅本模块、仅用户勾选、仅经改写与词典校验的文字允许烧录；通用默认仍是原片零文字。
- 实现路径：品牌字样不交给视频模型画（避免模型画字错误），由后端在复核通过后按创作脚本时间轴烧录；烧录后做真实视觉 OCR 复核，比对词典，违规标 `TEXT_VISION_MISMATCH` / needs_attention，原片保留核对。
- 改写约束：字幕与真人话术不得逐字复制原片；商业信息须经 LLM 改写并从文案层进入烧录流程。
- 能力缺口：系统当前无系统 ffmpeg/ffprobe、无 ASS/drawtext 烧录组件，烧录能力为 V4.149 必须新建项（本项目内实现，不引入独立大模型配置）。

## 七、页面设计与交互

页面三段式，均在 `#/imitatevideo` 内：

1. **新建任务区**：双 Tab（链接/上传）+ 第四章字段表单 + 商业信息四类勾选 + 权利声明勾选。
2. **脚本确认区**：分析脚本查看/导出；原片与新片结构对照；逐镜创作指令表（可改写旁白、删镜、排序、调结构保持度）；商业信息"原文→改写后"对照；预计消耗；"确认并生成"按钮。
3. **任务列表区**：状态、当前阶段、各阶段耗时、中间产物（脚本表/分段视频/音频）、成片预览与下载；全局 Dock 角标显示进行中任务数。

进度订阅提升到 App 层常驻（`useCreativeTasks` 上提），切页/刷新/关浏览器后任务不中断，回来可续看进度与状态。

## 九、大模型调用设计

| 环节 | 模型用途 | 输入 | 输出 | 失败策略 |
|------|---------|------|------|---------|
| 分析脚本 | analysis（复用 VLM 能力） | 源视频逐帧 | 分析脚本 JSON | 重试 1 次，失败标 unavailable |
| 创作脚本 | copy（文本模型） | 分析脚本 + 用户选项 | 创作脚本 JSON | 缩写重试 2 次 |
| 逐镜生成 | video（图生视频） | 干净首帧 + 运动 prompt | 分段视频 | 重试 1 次，降级 needs_attention |
| 视觉复核 | analysis（视觉） | 成片抽帧 | OCR 文本比对 | 不可用标 unavailable，不冒充通过 |

禁止 MockLLM/FallbackLLM 冒充交付；模型未配置或 `last_test_ok` 非 True → 422 拦截，不产生费用。

## 十、待确认事项确认结论（C-M1~C-M8）

用户对下列事项答复「没有异议」，全部按建议默认值执行，构成本任务书已冻结的参数：

| 编号 | 事项 | 冻结结论 |
|------|------|---------|
| C-M1 | 商业信息文字呈现 | 方案 A：烧录进成片；在三道防线上开受控例外（仅本模块、仅勾选、仅改写+词典校验） |
| C-M2 | 真人形象/口播 | 首期不做真人出镜；口播以改写文案交付、人工配音，不引入 TTS/数字人 |
| C-M3 | 视觉分析深度 | 逐镜 3–5 帧 + 全局取色 + VLM 逐帧理解，接受相应成本；不引入新模型用途 |
| C-M4 | 链接范围 | 首期仅直链 CDN；平台页解析（yt-dlp）列二期 |
| C-M5 | 权利与合规 | 强制勾选"已获授权/自有素材"并留痕来源 URL 与勾选记录 |
| C-M6 | 目标投放规格 | 新建任务必选目标平台+版位，从规格库取唯一规格；不跟随原片画幅 |
| C-M7 | 案例库共享范围 | 按 owner 隔离、任务私有沉淀；跨账号共享列二期 |
| C-M8 | 结构保持度档位 | 高/中/低三档；高=逐镜时长顺序全保留，中=保留钩子与 CTA，低=仅保留叙事骨架，均可逐镜微调 |

沿用上一轮默认值的其他口径：源视频 10–120 秒/≤200MB；viewer 不可见该菜单；关键操作写审计；不复制承诺性数字；目标语言英文/中文/跟随原片；AI 标识默认关闭、经理可开；成片归档 `CreativeAsset` + 下载。

## 十一、权限、合规与边界用例

### 11.1 权限

| 角色 | 权限 |
|------|------|
| admin/manager/editor | CAN_EDIT：创建、确认、下载、标记案例 |
| manager | CAN_REVIEW：查看全员任务与用量；可开启 AI 标识 |
| viewer | 不可见该一级菜单 |

创建/确认/生成/下载等关键操作写 `_audit()` 审计留痕。

### 11.2 合规

- 下载第三方视频二创须用户具备权利，强制勾选并留痕来源 URL 与勾选记录。
- 不复制原片承诺性数字、绝对化用语、未核实声明（A9 标记，创作脚本默认剔除）。
- AI 标识默认关闭，经理可按地区合规要求开启。
- 真实付费出片、真实视觉 OCR 抽检、品牌方确认属外部验收项，模拟测试不能替代。

### 11.3 边界用例

| 场景 | 处理 |
|------|------|
| 非直链/需登录/防盗链 | 提示改贴直链或走上传 |
| 私有网段 URL（SSRF） | 拦截 |
| 超 200MB / 非视频容器 | 明确失败原因 |
| 无音轨 / 无画面文字 | 标"无"，不猜测 |
| 模型未过 last_test_ok | 422 拦截，不产生费用 |
| 视觉模型不可用 | 标 unavailable，不冒充通过也不误伤成片 |
| 单段生成失败 | 重试一次后标 needs_attention，不阻塞整体 |
| 拿到 provider_task_id 后崩溃 | 重启按号续查，不重提、不重复计费 |

## 十二、技术开发流程与版本切分

每版独立验收、可回滚、tag + push、CHANGELOG 独立条目；不改动现有 4 个一级模块的功能与布局。

| 版本 | 内容 | 回滚方式 |
|------|------|---------|
| V4.145 | 骨架：一级菜单 + 页面壳 + 数据模型/迁移 + 上传链路复用 + 新 kind 任务状态机（不产生费用） | 移除菜单与页面 |
| V4.146 | 源视频获取：直链下载、本地上传、元数据、原片预览 | 开关关闭 |
| V4.147 | 分析脚本：逐帧解构 → 完整分析脚本 + 同链接缓存 + 查看/导出 | 开关关闭 |
| V4.148 | 创作脚本：统一 LLM + 确认闸门 + 成本预估 + 幂等 | 开关关闭 |
| V4.149 | 出片与复核：逐镜生成 + 续查不重提 + 拼接 + 规格强校验 + 烧录 + 视觉复核 + 下载归档 + 全局进度 | 开关关闭 |
| V4.150（可选） | 质量闭环：好/修改/重做标记 + 案例库沉淀 + 风格参考复用 | 独立开关 |

### 12.1 技术红线

- 不新建大模型配置模块；禁用 Mock/Fallback 冒充交付。
- 任务事实只有一份，禁止进程内任务字典；`kind=="video"` 硬编码需在 `_claim`/`recover`/`_drive` 三处放开。
- SQLite 时间统一 naive UTC；worker 每步释放 `lease_until`。
- 只有 `save_video_media` + `verify_video_file` 通过才算成功。
- 参考视频不是已核实产品事实，不能沿用落地页 `[E###]` 证据契约。

### 12.2 每版验收

专项 unittest + 隔离库全量回归 + `npx tsc --noEmit` + `npm run build` + `prepare_release --sync/--check` + CHANGELOG 独立版本条目 + tag + push。
