1需调用「文生图大模型」的功能模块及对应提示词

结论：平台此前 get_image() 为死代码，所有素材图均为 Pillow 模板渲染（即"背景都一样"的根因之一）。V4.18 已将文生图大模型接入生产链路——配置后按创意方向/风格/配色自动产出 AI 背景底图，再叠加广告版式。

关键发现：文生图大模型此前从未进入生成链路——providers.py 定义了 OpenAIImage 但 services.py 从未调用 get_image()。V4.18 以前，无论是否配置图像模型，图片都是 Pillow 模板。这正是你反馈"图片背景内容都一样"的深层原因之一（另一原因是创意方向 D 未驱动画面，已在 V4.16 修复）。

2现有大模型类型归纳（按需求目的：文案 / 图片 / 视频）

三个用途各对应一套提示词类型、输出结果与底层调用类型，互不复用，便于独立配置与调试。

A. 文案生成（usage = copy / analysis）

维度说明
提示词类型SYS_SITE_ANALYSIS（9 模块结构化分析）、SYS_ANGLE（8 创意方向）、SYS_COPY（标题/正文/CTA）
输出结果类型结构化 JSON：{angles:[...]} / {headlines,bodies,cta} / {positioning,value,proof,...}
大模型调用类型get_llm(db,"analysis"|"copy") → OpenAICompatibleLLM / AnthropicLLM / GeminiLLM（协议 openai/anthropic/gemini），失败回退 MockLLM

B. 图片生成（usage = image，文生图）

维度说明
提示词类型设计层 SYS_IMAGE_DESIGN（背景风格/版式/字号/意图）+ 运行时合成的文生图 prompt（_build_image_prompt()：产品+创意角度+风格+配色，要求"无文字/无 logo"）；版式叠加由 Pillow 完成
输出结果类型图像文件（PNG）。文生图模型产出背景底图，再由 render_creative 叠加广告版式（评分卡/折扣角标/对比/手机框/大字）输出最终素材图
大模型调用类型get_image(db) → OpenAIImage（协议 openai-image，DALL·E 等）或 GenericImageProvider（协议 generic-image，万相/CogView/SD/Replicate/即梦/自定义），未配置返回 None 回退 Pillow 模板

C. 视频生成（usage = video，文生视频）

维度说明
提示词类型SYS_VIDEO（15s 4 镜分镜脚本：钩子/演示/证明/CTA，visual 仅写拍摄说明、text 写上屏字幕）
输出结果类型① 未配视频模型：可执行分镜脚本（StoryboardVideo，含镜头/画面/字幕/口播/交付物）；② 配置后：真实视频文件/URL（mp4），关键帧由 render_creative(bg_path) 渲染
大模型调用类型get_video(db) → ModelVideo（协议 generic-video，POST /video/generations），失败回退 StoryboardVideo 分镜
三者解耦：改文案不影响图、改图不影响视频。调试时按 usage 维度分别查看「大模型管理」配置与「提示词管理」提示词即可定位问题。

3.3 统一归类视图（两张表如何对应）

提示词管理 = 说什么
5 条系统提示词，全部存 prompt_configs 表；
保存即生效、可停用/恢复默认；
调用方经 get_prompt(key) 读取（DB 优先，否则内置默认）。
调试某模块输出异常 → 先查对应 key 提示词。
大模型管理 = 用谁说
4 类 usage 各只允许 1 个激活配置；
存 model_configs 表（provider/key/url/model/params）；
未配置 → 自动回退 Mock/Pillow/分镜，主流程不中断；
调试某类不出结果 → 先查该 usage 是否配置且激活。
